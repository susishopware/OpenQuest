# Render deployment (demo)

`render.yaml` in the repository root is a Render Blueprint for the demo on the free plan, region Frankfurt. Render
deploys every push to the branch `deploy` of `susishopware/OpenQuest`.

| Service | Source | Domain | Notes |
|---|---|---|---|
| `openquest-web` | `Dockerfile.web` | openquest.fun | Next.js player app with the Jev tree search (`/api/tree-search`) |
| `openquest-karte` | `apps/dashboard/Dockerfile` | karte.openquest.fun | Tree dashboard with map and Jev search |
| `openquest-api` | `apps/api/Dockerfile` | api.openquest.fun | .NET API; applies the EF Core migrations and seeds the asset types on start |
| `openquest-minio` | `bitnamilegacy/minio` | | Photo storage, no disk on the free plan |
| `openquest-db` | managed Postgres 17 | | PostGIS database of the API and the importer |

The web app and the dashboard read the tree data from `packages/tree-search/data/trees.json` baked into their images
(`TREE_DATA_PATH`), not from the database.

## Configuration

- Render hands out the database credentials as separate values. `apps/api/docker-entrypoint.sh` builds
  `ConnectionStrings__Default` from `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` and
  `Storage__AccessKey` / `Storage__SecretKey` from `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` when those settings are not
  set. docker compose sets them directly, so nothing changes there.
- The API listens on 8080 (`ASPNETCORE_URLS` in its Dockerfile), so `PORT` is `8080`.
- Free web services cannot receive private network traffic, so the API reaches MinIO through its public URL
  (`Storage__ServiceUrl`).
- `OPENROUTER_API_KEY` is entered in the Render dashboard (`sync: false`), for `openquest-web` and `openquest-karte`.
- The admin password is generated by Render: openquest-api -> Environment -> `Admin__Password`.

## Importing the trees

The Python importer (`apps/importer`) fills the database; the API no longer syncs anything itself. On the free plan it
does not run on Render: cron jobs need a paid instance and have no disk, and a free web service would sleep. Run it from
your machine against the database's external URL instead, after the API of the same version has started once (it
seeds the tree schema the importer validates against):

```bash
docker build -f apps/importer/Dockerfile -t openquest-importer .
# Render -> openquest-db -> Connect -> External Database URL
docker run --rm \
  -e DATABASE_URL='postgresql://openquest:...@dpg-...-a.frankfurt-postgres.render.com/openquest?sslmode=require' \
  -e SYNC_INTERVAL_SECONDS=0 \
  -v openquest-importer-cache:/app/data/cache \
  -v openquest-importer-snapshots:/app/data/snapshots \
  openquest-importer
```

- `SYNC_INTERVAL_SECONDS=0` syncs all sources once and exits. The container waits up to 10 minutes for the schema.
- The first run of Münster fetches the nDOM heights (~10,300 WCS requests, about 9 minutes). The `importer-cache`
  volume keeps them, so later runs take seconds. The container stays well below 512 MB (about 150 MB measured).
- Snapshots of each download stay in the local `openquest-importer-snapshots` volume; `sync_run.snapshot_key` points
  there.
- The database must accept your IP: openquest-db -> Info -> Access Control.

The importer matches the trees spatially (ADR-0006). Assets created by the old C# sync keep their ids and
`external_id`s: the first run reports them all as `updated` (new raw record, street names, districts, quarters and
heights) and creates or removes nothing. The removal guard stops a run that would remove more than 20 % of the trees.

A paid alternative is sketched at the end of `render.yaml`: the importer as a daily Render cron job with
`DATABASE_URL` from the database's internal connection string.

## Free plan caveats

Services sleep after 15 minutes without traffic (the first request takes about a minute), the free Postgres expires
after 30 days, and MinIO has no disk (photos are lost on restart).
